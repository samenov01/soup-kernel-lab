## Реализация

Четыре собственных кернела в `solution/vocab.py` заменяют промежуточные
log-softmax тензоры при вычислении cross-entropy и entropy блочными статистиками.
Это один участок оптимизации: редукции по большому словарю.
Пример SwiGLU оставлен без изменений и не считается собственным.

В профиле организаторов softmax / cross-entropy занимают около 7% GPU-времени.
Это основание исследовать участок, но не измерение нового кандидата.
Изучены wheel-исходники закреплённых зависимостей. Патчи через `apply()`:

- Transformers `loss_utils.fixed_cross_entropy`: обучающий loss;
- TRL `sft_trainer.entropy_from_logits`: entropy под `no_grad`;
- Soup `rewind_hf.row_losses`: loss каждой строки и число supervised-токенов.

Глобальная `torch.nn.functional.cross_entropy` не заменяется. Повторный `apply()`
не дублирует патчи. Полные logits, штатная accuracy, логирование и адаптер
сохраняются. Настройки обучения, батчи, LoRA, optimizer и scheduler не меняются.

Словарь разбит на блоки по 4096 элементов. Каждый блок вычисляет максимум `m`,
сумму `s = sum(exp(x-m))` и, для entropy, момент `w = sum(exp(x-m)*(x-m))`.
Вторая редукция объединяет статистики с поправкой на максимумы блоков.
Хвосты маскируются. CE равен `logsumexp(x) - x[target]`; для `ignore_index`
результат нулевой. Нормализация использует исходный `num_items_in_batch` либо
число немаскированных токенов.

Autograd сохраняет logits, labels и один logsumexp на токен. Backward
пересчитывает вероятности внутри блока и записывает
`(softmax(x) - one_hot(target)) * upstream_gradient`, обнуляя игнорируемые строки.
Входы не перезаписываются. Вторые производные явно запрещены
`once_differentiable`; штатному обучению нужен первый порядок.
Полностью маскированный mean даёт NaN и нулевой градиент, как PyTorch.

Entropy вычисляется через центрированный момент без больших промежуточных
probabilities или log-probabilities. Временная память редукции:
O(tokens * ceil(vocab/4096)). Полные logits и градиент logits остаются:
это не доказательство снижения общего пика памяти.

Ускоряемый путь: CUDA fp32, единичный stride по словарю, labels типа long.
CE поддерживает разрывы между строками и неконтинуальные labels. Entropy
требует непрерывного входа без требуемого градиента. Остальные варианты
передаются исходным функциям, включая fp16 и differentiable entropy.
Transformers сам поднимает обучающий CE в fp32 при fp16 обучении;
режим модели ради оптимизации не меняется.

## Воспроизведение на Kaggle

GPU T4 x2, Internet on, Python 3.13. Harness использует только GPU 0.
Зависимости взяты из стартового ноутбука:

```bash
python -m pip install "soup-cli[train]==0.77.0" "transformers==5.16.1" "peft==0.20.0" "trl==0.29.1" "bitsandbytes==0.50.2" "accelerate==1.14.0" pytest
python task/prepare_data.py
python -m pytest solution -q
SOUP_APPLY_SOLUTION=1 python -m pytest tests -q
python harness/run_task.py --help
python harness/run_task.py --repeats 2 --profile
python harness/check_rules.py
python harness/score.py runs/result.json
```

Перед обучением оба набора тестов должны завершиться успешно. Harness сам
оценивает адаптеры через `eval_adapter.py`, измеряет полное время команды,
включая компиляцию, и выполняет base, solution, solution, base.
Профиль — дополнительный запуск. Не запускайте параллельные GPU-задачи.

Быстрая итерация:

```bash
python harness/run_task.py --only solution --profile --out runs_try_01
python harness/check_rules.py --result runs_try_01/result.json
```

Проверки сравнения с базой в этом режиме ожидаемо не проходят.
Harness очищает старые результаты в повторно используемых каталогах `--out`:
сохраняйте их заранее или выбирайте новое имя.

В `kaggle_team.ipynb` уже установлен URL личного репозитория, добавлены остановка при ошибках
тестов и запрет перезаписи существующего клона. `COMMIT` указывает на ветку
`main`. Для клонирования приватного репозитория добавьте в Kaggle секрет
`GITHUB_TOKEN` с правом чтения содержимого этого репозитория.
Для воспроизводимого замера задайте `COMMIT` точным SHA решения и сохраните версию
ноутбука. Её ссылку нужно добавить в SUBMISSION.md.

## Ограничения

Не подтверждены компиляция на T4, численная корректность, 79 регрессионных
тестов, качество адаптера, метрики, rewind, доля >=5% и выигрыш >=1.05.
Особенно рискован порог доли: исходные 7% GPU-времени не равны доле времени
обучения; ускорение редукций уменьшает их вклад. Нельзя утверждать,
что выбранного набора достаточно для допуска.

Единственный измеренный пользователем вариант — организаторский пример —
не проходит собственные кернелы и их долю. Другие оптимизации не испытывались.
Полные logits и их копия для accuracy могут сохранить пик памяти.
Следующий выбор оптимизации нужно делать по фактическому профилю,
не добавляя лишнюю работу ради порога.

## Источники идей и API

Код собственных кернелов написан заново; чужие реализации не переносились.

- [Triton fused softmax](https://triton-lang.org/main/getting-started/tutorials/02-fused-softmax.html):
  стабилизация максимумом, маски хвостов, редукции и сокращение обращений к памяти.
- [PyTorch 2.11 autograd](https://docs.pytorch.org/docs/2.11/notes/extending.html):
  autograd.Function, сохранение тензоров и backward.
- [Transformers 5.16.1](https://pypi.org/project/transformers/5.16.1/),
  [TRL 0.29.1](https://pypi.org/project/trl/0.29.1/),
  [Soup 0.77.0](https://pypi.org/project/soup-cli/0.77.0/): точные wheel-исходники
  для сохранения контрактов loss, entropy и rewind.
