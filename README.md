## Реализация

Четыре собственных кернела в `solution/vocab.py` заменяют промежуточные
log-softmax тензоры при вычислении cross-entropy и entropy блочными статистиками.
Это один участок оптимизации: редукции по большому словарю.
Пример SwiGLU оставлен без изменений и не считается собственным.

Ещё два собственных кернела в `solution/rmsnorm.py` объединяют frozen fp32
RMSNorm и его backward по входу. Forward считает inverse RMS и масштабирование
в одном проходе, backward — градиент с одной редукцией. Обучаемые нормы,
bf16-входы и неподдерживаемые layout сохраняют исходный путь Transformers.
Обычные fp16-вызовы тоже сохраняют прежний путь; специальный SFT fp16-путь
обрабатывается `half_activations.py` с FP32-арифметикой нормализации.

Кернел в `solution/nf4.py` распаковывает NF4-веса и умножает
значения штатной таблицы формата на масштабы блоков. Заменён общий примитив
деквантизации CUDA backend bitsandbytes 0.50.2: он обслуживает GEMM fallback
и backward по входу. Вложенные масштабы, квантованные веса и матричные умножения
остаются штатными. FP4/bf16 и неподдерживаемые layout используют исходный путь.

В профиле организаторов softmax / cross-entropy занимают около 7% GPU-времени.
Это основание исследовать участок, но не измерение нового кандидата.
Изучены wheel-исходники закреплённых зависимостей. Патчи через `apply()`:

- Transformers `loss_utils.fixed_cross_entropy`: обучающий loss;
- TRL `sft_trainer.entropy_from_logits`: entropy под `no_grad`;
- Soup `rewind_hf.row_losses`: loss каждой строки и число supervised-токенов.

Глобальная `torch.nn.functional.cross_entropy` не заменяется. Повторный `apply()`
не дублирует патчи. Accuracy, entropy, row-loss, логирование и адаптер
сохраняются. Настройки обучения, батчи, LoRA, optimizer и scheduler не меняются.

В поддерживаемом SFT training loss `solution/chunked_head.py` избегает хранения
полных logits: обрабатывает head по 256 строк, сохраняет нормализаторы и
пересчитывает supervised-строки в backward. Реальные метрики/rewind получают
те же необходимые значения. Внешние вызовы модели и evaluation сохраняют
полные logits. AMP scale применяется до fp16-округления градиента.
`compact_mlp.py` убирает лишние fp32-копии frozen MLP;
`padded_mlp.py` сокращает только детерминированную pointwise-работу на padding,
сохраняя порядок батчей и формы dropout. [Предыдущие контракты и замеры](docs/T4_RUN_04.md).

В новой версии `rope.py` объединяет RoPE без специализаций каждой длины батча;
`projection_io.py` — gather/cast и scatter/zero-fill. `merged_gate_up.py` и
`merged_qkv.py` объединяют frozen-проекции, сохраняя исходные параметры и
только дополнительные packed-NF4 buffers. `compact_lora.py` оставляет A/B
компактными и объединяет scatter, scaling и add, сохраняя порядок округления.

`half_activations.py` хранит внутренние decoder-активации в FP16 при FP32
статистиках и производных нормализации; final norm возвращает FP32 для head.
Веса, dtype обучаемых параметров и fp16/bf16-флаги не меняются.
Это меняет округление residual/промежуточных значений: побитовая тождественность
прежним FP32-активациям не заявляется, включая битовые маски dropout разных dtype.
Native dropout сохраняет p и формы; реальные метрики, кривая и adapter eval
прошли исходные проверки. [Точное описание и границы](docs/T4_RUN_07.md).

`unpadded_sdpa.py` вызывает native causal SDPA для действительных диапазонов
внутри каждой строки, затем возвращает результаты в исходные позиции.
Батчи, порядок строк и optimizer steps не меняются; supervised-запросы в
padding и неподдерживаемые маски сохраняют прежний путь. Отдельного
подтверждённого ускорения относительно предыдущего кандидата пока нет:
измерения разных сессий дают сопоставимые 1.37–1.39x при меньшем новом пике.

Словарь разбит на блоки по 4096 элементов. Каждый блок вычисляет максимум `m`,
сумму `s = sum(exp(x-m))` и, для entropy, момент `w = sum(exp(x-m)*(x-m))`.
Вторая редукция объединяет статистики с поправкой на максимумы блоков.
Хвосты маскируются. CE равен `logsumexp(x) - x[target]`; для `ignore_index`
результат нулевой. Нормализация использует исходный `num_items_in_batch` либо
число немаскированных токенов.

В обычном CE-пути autograd сохраняет logits, labels и отдельно максимум и логарифм суммы
центрированных экспонент на токен. Backward
пересчитывает вероятности внутри блока и записывает
`(softmax(x) - one_hot(target)) * upstream_gradient`, обнуляя игнорируемые строки.
Входы не перезаписываются. Вторые производные явно запрещены
`once_differentiable`; штатному обучению нужен первый порядок.
Полностью маскированный mean даёт NaN и нулевой градиент, как PyTorch.

Entropy вычисляется через центрированный момент без больших промежуточных
probabilities или log-probabilities. Временная память редукции:
O(tokens * ceil(vocab/4096)). Сам этот CE-путь сохраняет полные logits;
новый training head ограничивает их размер блоком отдельно.

Ускоряемый путь: CUDA fp32, единичный stride по словарю, labels типа long.
CE поддерживает разрывы между строками и неконтинуальные labels. Entropy
требует непрерывного входа без требуемого градиента. Остальные варианты
передаются исходным функциям, включая fp16 и differentiable entropy.
Transformers сам поднимает обучающий CE в fp32 при fp16 обучении;
режим модели ради оптимизации не меняется.

## Воспроизведение на Kaggle

GPU T4 x2, Internet on, Python 3.13. Harness использует только GPU 0.
Зависимости взяты из стартового ноутбука:

```bash
python -m pip install "soup-cli[train]==0.77.0" "transformers==5.16.1" "peft==0.20.0" "trl==0.29.1" "bitsandbytes==0.50.2" "accelerate==1.14.0" pytest
python task/prepare_data.py
python -m pytest solution -q
SOUP_APPLY_SOLUTION=1 python -m pytest tests -q
python harness/run_task.py --help
python harness/run_task.py --repeats 2 --profile
python harness/check_rules.py
python harness/score.py runs/result.json
```

Перед обучением оба набора тестов должны завершиться успешно. Harness сам
оценивает адаптеры через `eval_adapter.py`, измеряет полное время команды,
включая компиляцию, и выполняет base, solution, solution, base.
Профиль — дополнительный запуск. Не запускайте параллельные GPU-задачи.

Быстрая итерация:

```bash
python harness/run_task.py --only solution --profile --out runs_try_01
python harness/check_rules.py --result runs_try_01/result.json
```

Проверки сравнения с базой в этом режиме ожидаемо не проходят.
Harness очищает старые результаты в повторно используемых каталогах `--out`:
сохраняйте их заранее или выбирайте новое имя.

В `kaggle_team.ipynb` уже установлен URL личного репозитория, добавлены остановка при ошибках
тестов и запрет перезаписи существующего клона. `COMMIT` закреплён на
`160150ef7560289f520710ce5982918e0cb1d5fb`.
Репозиторий публичный, для клонирования `GITHUB_TOKEN` не нужен. Сохраните версию
ноутбука. Её ссылку нужно добавить в SUBMISSION.md.

## Ограничения

Минимальная доля собственных кернелов — 11.70%; на скрытых данных она может
измениться. Автоматический
допуск не заменяет ручную проверку жюри. Выигрыш по памяти относится к
совокупности патчей; новая версия существенно ниже прежнего SwiGLU-примера.
Выигрыш по времени относится ко всему решению относительно Soup в одной
сессии; вклад отдельного RMSNorm требует прямого сравнения solution-версий.
Цель ≥2x по памяти достигнута, 2.5x по полному времени — пока нет.
Настройки и критерии задачи не менялись. Следующие эксперименты должны
сравниваться с этой проверенной версией, без искусственного увеличения доли.

## Источники идей и API

Код собственных кернелов написан заново; чужие реализации не переносились.

- [Triton fused softmax](https://triton-lang.org/main/getting-started/tutorials/02-fused-softmax.html):

  autograd.Function, сохранение тензоров и backward.
- [Transformers 5.16.1](https://pypi.org/project/transformers/5.16.1/),
  [TRL 0.29.1](https://pypi.org/project/trl/0.29.1/),
  [Soup 0.77.0](https://pypi.org/project/soup-cli/0.77.0/): точные wheel-исходники
  для сохранения контрактов loss, entropy и rewind.
- bitsandbytes 0.50.2: точные wheel-исходники контракта деквантизации и
  штатная таблица значений формата NF4; код его CUDA-кернелов не копировался.
