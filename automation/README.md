# Автоматические эксперименты Kaggle

Приватный ноутбук аккаунта пользователя:
https://www.kaggle.com/code/diassamenov/soup-kernel-lab-auto

Авторизация выполняется официальным Kaggle CLI через `kaggle auth login`.
Секреты хранятся в стандартной пользовательской конфигурации CLI, не в репозитории.
Если CLI отсутствует в PATH, скрипт ищет Windows user Scripts или использует
переменную окружения `KAGGLE_CLI` с полным путём к исполняемому файлу.

## Команды на локальном компьютере

```bash
python automation/kaggle_control.py prepare --commit FULL_GIT_SHA
python automation/kaggle_control.py submit --commit FULL_GIT_SHA
python automation/kaggle_control.py status
python automation/kaggle_control.py download --version 1 --out artifacts/kaggle_auto/version_1
```

`prepare` только готовит исходники; `submit` создаёт новую сохранённую версию
и запускает её на NvidiaTeslaT4 (T4 x2). Запуск расходует обычную GPU-квоту Kaggle.
Проверяется, что первая GPU — T4; штатный harness использует только GPU 0.
Полный SHA в аргументе должен быть опубликован в личном GitHub-репозитории.

`status` проверяет состояние. После завершения `download` скачивает
`kernel_results.zip` и `run_status.json`, а не тяжёлые адаптеры и кэши.
Папка скачивания должна быть новой/пустой. Выбирайте точную версию, чтобы
не смешать результаты разных запусков. Имя исходного пользовательского
ноутбука не используется и он этими командами не обновляется.

## Сценарий внутри Kaggle

`kaggle_job.py` встраивается в один code cell notebook; Git URL и SHA
встраиваются из аргументов при подготовке. Метаданные запрашивают приватность,
T4 и Internet. Далее выполняются:

1. Проверка GPU и установка закреплённых зависимостей стартового проекта.
2. Клонирование личного публичного репозитория и checkout точного SHA.
3. Подготовка данных штатным скриптом.
4. `pytest solution` и регрессионные тесты с `SOUP_APPLY_SOLUTION=1`.
5. Неизменённый harness: `--repeats 2 --profile`.
6. `check_rules.py` и `score.py`.

Каждая команда пишет лог; ошибка останавливает следующий этап.
В `finally` создаются статус и ZIP с логами/JSON/YAML из результатов,
включая ошибки unit-тестов или допуска. Если Kaggle принудительно завершает
процесс/VM до выполнения finally, архив может отсутствовать — тогда нужно
получить платформенные логи.

Обучающий конфиг, harness, task и тесты организаторов не меняются.
Сохранённые адаптеры остаются в каталоге runs; ZIP просто исключает их
и компиляторные кэши для удобства скачивания.
