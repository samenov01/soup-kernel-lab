## Что проверено у RMSNorm

Forward запущен 3648 раз в каждом полном solution-запуске,
backward — 3584 раза. В 16 профильных шагах: forward 912 вызовов,
67.208 мс; backward 896 вызовов, 95.596 мс.
Новые кернелы реально используются, frozen weight и fallback протестированы.
Предыдущие отдельные pow/rsqrt-кернелы в профиле больше не встречаются.

## Границы выводов

Сравнение в этой сессии — исходный Soup против всей совокупности патчей.
Нельзя приписывать RMSNorm весь speedup 1.0814x: предыдущий кандидат
измерялся в другой сессии, а base_1/base_2 здесь отличаются по времени.
Прямое сравнение двух solution-версий в одной сессии пока не выполнялось.

Минимальная доля 8.10% даёт больший запас над порогом, чем прежние 5.93%.
Доля на скрытых данных и решение жюри по-прежнему не гарантируются.
Изменение пика относительно прежних 12385 MiB составляет только 2 MiB:
это не основание заявлять дополнительный memory gain от RMSNorm.
Основной прежний выигрыш памяти уже наблюдался с примером SwiGLU.

## Сохранение и дальнейшая работа

Предыдущая проверенная версия остаётся в метке `t4-validated-v2`.
Эта версия сохраняется меткой `t4-validated-rmsnorm-v3` на проверенном SHA.
Обновления отчётов и автоматизации не меняют solution после измерения.

Для окончательной сдачи ещё нужны публичная сохранённая Kaggle-версия,
перенос проверенного решения в репозиторий команды, видео, презентация
и данные участников. Текущий автоматический ноутбук приватный; его запуск
не публикует конкурсную сдачу и не меняет репозиторий команды.
