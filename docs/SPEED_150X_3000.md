# Кандидат: s ≥1.5 и внешний пик <3000 MiB

Статус: подготовлен новый кандидат в личной ветке `speed-under-3000`.
Ни целевая скорость, ни пик, ни полный допуск этой версии пока не измерены.
Публикация в репозиторий хакатона приостановлена по просьбе пользователя.

## Цель и исходные данные

При базе 79 с для s=1.5 нужно полное время ≤52.6667 с. В зачёт идёт
отношение результатов одной сессии; подставлять условные 79 с вместо
реально измеренной базы нельзя. При базе 76.69 с потребуется ≤51.1267 с.
Время включает запуск процесса, загрузку модели, компиляцию, обучение и
сохранение адаптера, а не только training loop.

Пользователь сообщил первый повтор `eacf459`: 76.69 с / 14345 MiB у базы,
71.62 с / 1713 MiB у решения (s=1.07079). Полного архива этого запуска нет.
Результат следующего кандидата `c9a2ead` с бюджетом 192 MiB ещё не предоставлен.
Проверенный результат 817 MiB относится к более медленному `8eb46a3`.

## Что изменено

1. Общий бюджет удержания saved-активаций на GPU увеличен до 896 MiB.
   Это не выделение резерва: удерживаются только реально сохранённые тензоры.
   При переполнении обычные активации продолжают переноситься на CPU.
2. Forward MLP пытается сохранить уже вычисленные gate/up в этом же бюджете.
   Резервирование пары атомарно, общие storage учитываются один раз.
   При успехе backward использует точные сохранённые значения, без повторного
   gate/up GEMM; узкий вход x тогда не сохраняется. Если места недостаточно,
   используется прежний детерминированный пересчёт из x. Дополнительного
   отдельного бюджета на каждый слой нет.
3. Блок выходного слоя увеличен с 256 до 512 токенов. Количество вызовов
   GEMM и редукций уменьшается, промежуточные logits становятся больше.
   Используется весь словарь, те же labels, CE, entropy, accuracy и rewind.
4. Сохраняются resident MLP NF4, повторно используемый Half-операнд head,
   раннее CPU-хранение FP32 embedding/head и reuse decoded gate/up в
   recompute-backward для больших входов T4 из предыдущих кандидатов.

Решение сохранить gate/up определяется только фактическим размером тензоров
и остатком бюджета в обычном forward. Оно не зависит от номера шага,
таймера, profiler, тестов, seed или конкретных данных задачи. Callback
изолирован ContextVar и сбрасывается в finally после forward, в том числе
при исключении. Сохранённые значения доступны обычному autograd.

## Оценка памяти и риски

Базовые frozen NF4-матрицы занимают около 624.75 MiB, Half-операнд head —
445.125 MiB. К ним добавляются saved-активации до 896 MiB, scales, LoRA,
optimizer state, рабочие тензоры и CUDA runtime. Один logits-блок Half
размером 512×151936 занимает 148.375 MiB; в backward одновременно нужен
градиент такого же размера. FP16 gate/up вес одного слоя — 52.5 MiB.

Относительно наблюдённых 1713 MiB грубая оценка дополнительных тензоров:
832 MiB бюджета, до 148.375 MiB на увеличение пары logits/dlogits и
52.5 MiB на удержание decoded gate/up. Сумма около 2746 MiB — только
ориентир, не доказательство внешнего пика <3000 MiB. Аллокатор, время жизни
буферов и компиляция могут изменить максимум. Скрипты измерения не меняются.

Ускорение на 1.5× не гарантируется увеличением памяти. Из исходных 71.62 с
надо убрать около 19–20 с; CPU overhead и стоимость полного запуска тоже
входят в цель. При неудаче публиковать кандидату целевые цифры нельзя.

## Проверки

- Тест MLP проверяет сохранение и отказ при нулевом бюджете, обе стороны
  сравниваются с прежними outputs и scaled gradients с нулевым допуском.
  Покрываются реальные width=1536/intermediate=8960, padding и small-M.
- Для retained-пути тест запрещает повторный bnb.matmul_4bit в backward и
  проверяет, что сохраняется gate/up, а не x.
- Тест storage-бюджета проверяет атомарный отказ и однократный учёт aliases.
- Тест head дополнен 513 токенами и полным словарём 151936: переход через
  новую границу 512, true metrics и реальный AMP scale 65536.
- Локально доступны только синтаксис и статический аудит, PyTorch/CUDA нет.
  GPU-тесты и два полных повтора необходимо выполнить на Kaggle T4.

Модель, данные, батчи, число шагов, LoRA/dropout, optimizer/lr, fp16/bf16,
встроенные режимы Soup и аллокатор не изменены. `harness/`, `tests/`,
`task/`, `templates/` совпадают с исходной версией организаторов.
Обязательны все 10 PASS, внешний пик <3000 MiB и фактический s≥1.5.

Это изменения хранения и гранулярности вычислений; сторонние kernel-библиотеки
не добавлены. Пример SwiGLU остаётся исключён из доли собственных кернелов.
Долю ≥5% необходимо заново проверить: сокращение пересчёта может её изменить.
