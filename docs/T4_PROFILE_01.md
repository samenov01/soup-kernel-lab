## Выбор следующей операции

Добавлена собственная NF4-деквантизация: `solution/nf4.py`.
Её выход — реальные веса для штатных матричных умножений прямого прохода
и расчёта градиента по входу. Это дополнительная полезная работа вместо
соответствующей операции bitsandbytes; лишних запусков нет.

В bitsandbytes 0.50.2 прямой проход `MatMul4Bit` использует `gemm_4bit`,
а backward — `functional.dequantize_4bit`. Простая подмена только публичной
functional-функции пропустила бы часть прямого прохода. Поэтому заменена
общая `_dequantize_4bit_impl` в CUDA backend. Исходники изучены из wheel
bitsandbytes 0.50.2; код чужих кернелов не переносился.

Новый кернел распаковывает старший/младший полубайты, читает значение
из штатной 16-элементной таблицы формата NF4 и умножает на масштаб блока.
Вложенные масштабы, квантованные веса, dtype, выделение буферов и GEMM
сохраняют путь bitsandbytes. Кэшируется только таблица из 16 констант,
не веса и не компилированные программы. FP4, bf16 и неподдерживаемые
layout передаются исходной реализации.

## Проверка нового кандидата

Локально: Python syntax / compileall и штатный статический анализ успешны.
Распознаны пять собственных кернелов, без запрещённых импортов и сходства
с SwiGLU-примером. `pytest solution/test_nf4.py` остановился при collection:
локально отсутствует torch. На T4 новый NF4-кернел ещё не проверен.

Добавлены 16 GPU-тестов: nested/non-nested NF4, fp16/fp32, формы Qwen,
разные размеры блока, нечётный хвост, все 16 кодов, предоставленный out,
transpose shim, сохранность входов, повторный apply, FP4 fallback,
реальные bitsandbytes matmul forward и input-gradient.
Требуется точное совпадение с bitsandbytes: арифметика здесь только lookup
и одно умножение fp32 с тем же масштабом.

Порог 5% не гарантирован. Если новый кернел сильно ускорит деквантизацию,
его вклад уменьшится. Фактический допуск решает штатный harness;
искусственно замедлять кернел или добавлять работу нельзя.

Следующий запуск: сначала `python -m pytest solution -q`, затем
`python harness/run_task.py --repeats 2 --profile --out runs_nf4_01` и
`python harness/check_rules.py --result runs_nf4_01/result.json`.
Только при успешных численных тестах переходить к обучению.
