# Следующая итерация: frozen fp32 RMSNorm

Проверенная версия сохранена меткой `t4-validated-v2`, указывающей на
`b59719c3f60878776d297ecdea185083f768fdbd`. Эксперимент живёт в отдельной ветке
`rmsnorm-experiment`. Результаты 10/10 предыдущего запуска не относятся
к этому изменению, пока оно не проверено на T4.

## Основание выбора

Профиль `docs/measurements/t4_v2/profile.json`: за 16 активных шагов
912 вызовов square/pow, 912 rsqrt. Это совпадает с 57 нормализациями Qwen
на шаг: 28 слоёв по две нормы и одна финальная норма.
Square занимает 67.076 мс, rsqrt 2.990 мс; сводный mean занимает 44.856 мс
с 944 вызовами и включает также другие операции. Нельзя приписывать нормам
всё время общих multiply/copy-кернелов из агрегированного профиля.

Цель: объединить нормализацию и её input-gradient, сократив запуски и
промежуточные тензоры. Не утверждаем конкретный выигрыш по времени или памяти.
У frozen нормы исходный autograd уже сохраняет ссылки на вход и малые
статистики, поэтому исчезновение временных тензоров может не снизить общий пик.

## Реализация

`solution/rmsnorm.py` добавляет два собственных кернела:

- forward: `r = rsqrt(mean(x*x) + eps)`, `y = (x*r)*weight`;
- backward: `h=x*r`, `g=dy*weight`,
  `dx = r * (g - h * mean(g*h))`.

Сохраняются вход, замороженный weight и один inverse RMS на строку.
Параметры не добавляются, остаточные связи и другие части Qwen не патчатся.
Оба кернела выполняют только необходимые вычисления, без повторов ради доли.

Ускоряется только непрерывный CUDA fp32 вход и fp32 frozen weight,
положительный конечный eps, ширина 1–16384. Остальные входы, включая
fp16/bf16, обучаемые веса, CPU и непрерывность с разрывами, сохраняют
исходный `Qwen2RMSNorm.forward` из Transformers 5.16.1.
Вторые производные явно не поддерживаются для ускоренного пути.
Обучение по условиям использует первый порядок и замороженные нормы.

## Проверки

22 новых GPU-теста: forward/backward для форм задачи и некратных ширин,
нулевые и малые значения, большие конечные значения, неконтинуальный grad,
сохранность входов, fallback с обучаемым weight, fp16, CPU, разрывами,
пустым тензором; модельный тест маленького Qwen без скачивания весов.
Fixture проверяет фактические запуски нового forward-кернела.
Допуски учитывают порядок fp32-редукции; полные проверки loss/rewind/качества
в штатном harness всё равно обязательны.

Локально прошли syntax/compileall, анализ штатной функцией source_kernels:
семь собственных кернелов, без запрещённых импортов и похожих на пример.
Неизменность harness/tests/task/templates подтверждена относительно стартера.
Независимая CPU float64-проверка формулы backward конечными разностями
прошла на 12 наборах ширин и масштабов; это не выполнение GPU-кернелов.
GPU-pytest локально остановился при collection из-за отсутствия torch.

## Следующее измерение

После получения ветки в Kaggle сначала выполнить все тесты `solution`.
Ожидается 68 тестов (46 прежних + 22 новых). При ошибке остановиться.
Затем:

```bash
python harness/run_task.py --repeats 2 --profile --out runs_rmsnorm_01
python harness/check_rules.py --result runs_rmsnorm_01/result.json
```

Использовать новое имя каталога, если такое уже существует, чтобы сохранить
предыдущие результаты. Не менять task.yaml или число шагов обучения.
Сравнить память, полное время, loss, метрики и долю с сохранённой версией.
Если нет полезного выигрыша или нарушены допуски, вернуться к сохранённой метке.

## Источники идей и API

- [RMSNorm в PyTorch 2.11](https://docs.pytorch.org/docs/2.11/generated/torch.nn.RMSNorm.html):
  математическое определение нормы.
- [Triton Layer Normalization](https://triton-lang.org/main/getting-started/tutorials/05-layer-norm.html):
  общий принцип объединения нормализации и input-gradient с редукцией по строке.
  Чужой kernel-код и библиотеки из примера не копировались и не импортировались.
- Точный `Qwen2RMSNorm.forward` из wheel Transformers 5.16.1 — контракт
  выходного dtype, порядка операций и fallback.
