# Повторный аудит реализации

Исследована версия `be9fe20cfea38a632857d3b2583df693554afa17`,
код закреплённых bitsandbytes/Transformers/TRL/Soup и ранее полученный T4-профиль.
Новые изменения не измерены на T4. Числа ниже относятся к независимым
CPU-расчётам формул, а не к запуску Triton.

## 1. Потеря точности backward при общем смещении logits

Прежний код сохранял `maximum + log_sum` одним fp32-числом, затем вычислял
`exp(x - saved_lse)`. При 8193 одинаковых logits, равных 1e6, CPU fp32
воспроизведение даёт сумму вероятностей 1.01109648 вместо 1.0:
относительная ошибка вероятности около 1.11%. Forward уже использовал
центрированную формулу и мог пройти тест, скрыв ошибку backward.

Теперь сохраняются два числа: `maximum` и `log_sum`.
Backward вычисляет `exp((x - maximum) - log_sum)`. В том же CPU-примере
сумма равна 1.00000024. Добавлены сравнения loss и градиентов с PyTorch
для общих смещений +1e6, -1e6 и +1e8.

Цена — ещё один fp32 на токен: при 2048 токенах это 8 KiB.
Это исправление численной устойчивости, не заявка на ускорение.
В полученном обычном запуске T4 подобная ошибка не наблюдалась.

## 2. Полностью маскированный блок классов

Если один блок из 4096 logits целиком равен -inf, его локальный максимум
тоже -inf. Прежнее вычитание даёт NaN, который попадает в итоговую сумму,
даже когда другой блок содержит допустимые классы.

Для CE такой блок теперь вносит нулевую сумму. Добавлены тесты для первого
и второго блоков, обычного ignore_index=-100 и положительного ignore_index=3.
Семантика entropy для нечисловых входов не менялась: исходная функция TRL
также вычисляет произведение вероятности и log-probability и может дать NaN.
Строка, в которой вообще все классы равны -inf, не объявляется допустимым
распределением и не получает искусственный конечный loss.

Независимый NumPy-расчёт новых формул проверен на 7 наборах: нулевые logits,
три общих смещения, два маскированных блока, случайный вход.
Максимальная абсолютная ошибка вероятности против float64 — 8.07e-10.
Это не заменяет GPU-тесты в `solution/test_vocab.py`.

## 3. Лишние синхронизации при записи rewind

Прежняя обёртка делала `float(tensor)` и `int(tensor)` для каждой строки.
При batch=4 это восемь последовательных переносов скаляров на CPU.
Теперь средние и целочисленные счётчики собираются отдельно на GPU,
после чего два списка переносятся на CPU через `tolist()`.

Порядок строк, float32-редукция, int64-счётчики и формат возвращаемых списков
сохранены. Ускорение не измерено; в профиле нет CPU-трассы, позволяющей
приписать этим синхронизациям конкретную долю общего времени.
Существующий интеграционный тест сравнивает результаты с Soup,
включая полностью игнорируемую строку.

## 4. Проверка фактического подключения NF4

Одного совпадения с bitsandbytes недостаточно: тест мог бы пройти,
если обёртка всегда уходила бы в исходную реализацию.
В тестовой fixture теперь считаются реальные вызовы нового Triton-кернела.
Проверяется запуск для обычной деквантизации, out, transpose и обеих частей
matmul forward/backward; для FP4 проверяется отсутствие нового запуска.
Это только наблюдение в тестах; production-код не узнаёт о тестах и
не меняет поведение под ними.

## Результат локальной проверки

Синтаксис Python, compileall, анализ исходников штатной функцией harness
и неизменность `harness/`, `tests/`, `task/`, `templates/` проверены.
GPU-тесты локально недоступны: нет PyTorch/Triton в поддерживаемом окружении.
Не утверждаем ни новый speedup, ни достижение доли >=5%.

По профилю приведения/копии занимают около 19.18% GPU-времени, но имена
сводных CUDA-кернелов не привязывают их однозначно к конкретным Python-операциям.
Поэтому дополнительная глобальная подмена dtype/copy не вводилась.

- [PyTorch 2.11 log_softmax](https://docs.pytorch.org/docs/2.11/generated/torch.nn.functional.log_softmax.html):
  стабильное вычисление значения и градиента служит контрактом сравнения.
- [Triton exp](https://triton-lang.org/main/python-api/generated/triton.language.exp.html):
  примитив экспоненты в наших формулах.
- Закреплённые wheel-исходники: Transformers 5.16.1 `loss_utils.py`,
  TRL 0.29.1 `utils.py`, Soup 0.77.0 `rewind_hf.py`,
  bitsandbytes 0.50.2 `functional.py`, `backends/cuda/ops.py`.
